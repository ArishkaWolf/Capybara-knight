# Подготовка мобильного релиза

Проект сохраняет бессерверную архитектуру. Браузерная версия публикуется целиком из `dist/`; Android и iOS используют тот же сюжет и интерфейс. APK, AAB и IPA в рамках этой подготовки не создавались.

## Изображения

Оригиналы остаются в `photo/`. `npm run prepare:story` создаёт WebP с качеством 82 и размером до 1920 × 1080 без увеличения, обрезки или изменения пропорций. Обрабатываются также картинки, ещё не подключённые к сюжету. При повторном запуске неизменившийся арт не перекодируется.

- `assets/story/` — оптимизированные картинки для мобильного приложения.
- `assets/story.json` — встроенная копия сюжета с путями к WebP.
- `assets/image-manifest.json` — размеры, объёмы и контрольные суммы оригиналов и результатов.
- `src/assets.ts` — автоматически созданные ссылки на картинки. Вручную менять этот файл не нужно.
- `assets/branding/`, `public/icons/` — иконки и изображение экрана запуска, подготовленные из существующего арта.

Редактируй только `public/story.json` и исходный арт. При изменениях увеличивай `version` сюжета. Сборка веб-версии публикует оптимизированный `dist/story.json` и убирает из `dist/photo/` тяжёлые PNG. Идентификаторы сцен, игровые переменные, области поиска и сохранения остаются совместимыми. Стандартные команды запуска автоматически готовят изображения.

## Интерфейс

Выбор игрока и главное меню работают в обеих ориентациях. На узких экранах карточки игроков складываются вертикально. Форма имени прокручивается при открытой клавиатуре; на Android окно изменяет размер, на iOS форма учитывает клавиатуру.

История рассчитана на горизонтальный экран. Нативное приложение запрашивает поворот при переходе к истории и освобождает ориентацию в меню. В браузере остаётся подсказка повернуть телефон и возможность вернуться в меню. Экран учитывает динамическую высоту окна браузера, вырезы и нижний системный индикатор.

У кнопок и областей предметов минимальная область нажатия 48 × 48 логических пикселей. Картинка интерактивной сцены и предметы используют одну геометрию внутри безопасной области. Длинные реплики, варианты выбора, меню и финал прокручиваются. Анимация текста приостанавливается при открытом меню и уходе приложения в фон. Кнопка «Назад» Android открывает игровое меню; из главного меню возвращает к игрокам.

`expo-image` поддерживает WebP на Android и iOS и сохраняет загруженные изображения в дисковом кэше. Для встроенной версии при недоступности удалённой картинки используется её встроенная копия. Новые удалённые сцены требуют доступного изображения или ранее заполненного кэша. Веб-манифест и иконки позволяют добавить ярлык на домашний экран в поддерживающих это браузерах. Service worker не добавлен: полного офлайн-режима веб-версии пока нет.

## Проверка на телефоне без APK

```powershell
npm install
npm run build:web
npm run preview:lan
```

Сервер напечатает IP-адрес компьютера. Открой адрес на телефоне в той же Wi-Fi сети. Обычный `npm run preview` доступен только на компьютере. Для проверки запуска с домашнего экрана и поведения HTTPS используй опубликованную статическую сборку; HTTP в локальной сети подходит для проверки интерфейса.

Для нативной проверки можно запускать `npm start` и открывать приложение в Expo Go, совместимом с SDK проекта. Экран запуска и окончательное поведение системных панелей нужно проверить позднее в самостоятельной сборке. Настоящий iPhone/Android в автоматической браузерной проверке не участвует.

## Проверка сборки

```powershell
npm run prepare:story
npm run check
npm test
npm run build:web
npm run check:mobile
```

Последняя команда экспортирует JavaScript и ресурсы Android/iOS в `artifacts/mobile-export/`. Она проверяет сборку двух платформ и не создаёт APK/IPA.

## Публикация и дальнейшая мобильная сборка

Для браузера размести содержимое `dist/` на статическом HTTPS-хостинге. Пути манифеста и иконок относительные, поэтому поддерживается публикация в подпапке. Для `story.json` требуется `Cache-Control: no-store`; при размещении данных на отдельном домене разреши CORS. `public/_headers` содержит готовые правила для хостингов, понимающих этот формат; на других настрой эквивалентные заголовки. При обновлении сначала загружай новые картинки, затем JSON. Не удаляй изображения предыдущей версии немедленно: открытые игры могут ещё использовать её.

Для обновлений нативного приложения задай `EXPO_PUBLIC_STORY_URL` по `.env.example` до сборки. Без него встроенный сюжет запускается локально, но удалённые обновления не проверяются. Адрес сервера и учётные данные магазинов в проект не добавлены.

`app.json` содержит иконку, адаптивную иконку Android, настройки экрана запуска, идентификаторы приложения и номера сборок. `eas.json` подготовлен для будущих внутренних и магазинных сборок. Перед первой реальной сборкой потребуется привязать проект к своему аккаунту Expo и подтвердить окончательные идентификаторы; для iOS потребуется настройка подписи Apple. Автоматическая проверка экспорта не проверяет подпись, нативную компиляцию или готовность к публикации в магазине.

Перед релизом проверь на настоящем Android и iPhone: ввод имени с клавиатурой, поворот в обе стороны, длинные реплики и выборы, поиск трёх улик и записку, уход в фон/возврат, перезапуск с сохранениями нескольких игроков, обновление сюжета, экран запуска и системную кнопку «Назад» Android. Проверь отдельно запуск из браузера и с ярлыка домашнего экрана. На iOS нужные проверки включают Safari и вырез/нижний индикатор; на Android — Chrome и системную навигацию.
