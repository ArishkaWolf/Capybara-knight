# Подготовка мобильного релиза

Браузерная версия доступна на [GitHub Pages](https://arishkawolf.github.io/Capybara-knight/) на ПК, телефонах и планшетах. Нативная версия опубликована в Expo: постоянный QR-код для iOS/Android находится в README. Android APK собирается и проверяется отдельным GitHub Actions workflow, затем публикуется в Releases. Отдельная IPA для iPhone требует подписи Apple и пока не выпускается.

## Изображения

Оригиналы остаются в `photo/`. `npm run prepare:story` создаёт WebP с качеством 82 и размером до 1920 × 1080 без увеличения, обрезки или изменения пропорций. Обрабатываются также картинки, ещё не подключённые к сюжету. При повторном запуске неизменившийся арт не перекодируется.

- `assets/story/` — оптимизированные картинки для мобильного приложения.
- `assets/story.json` — встроенная копия сюжета с путями к WebP.
- `assets/image-manifest.json` — размеры, объёмы и контрольные суммы оригиналов и результатов.
- `src/assets.ts` — автоматически созданные ссылки на картинки. Вручную менять этот файл не нужно.
- `assets/branding/`, `public/icons/` — иконки и изображение экрана запуска, подготовленные из существующего арта.

Редактируй только `public/story.json` и исходный арт. При изменениях увеличивай `version` сюжета. Сборка веб-версии публикует оптимизированный `dist/story.json` и убирает из `dist/photo/` тяжёлые PNG. Идентификаторы сцен, игровые переменные, области поиска и сохранения остаются совместимыми. Стандартные команды запуска автоматически готовят изображения.

## Интерфейс

Весь интерфейс рассчитан на горизонтальный экран. Список игроков и форма имени прокручиваются; на Android окно изменяет размер при клавиатуре, на iOS форма учитывает её.

В вертикальном положении игра, главное меню и выбор игрока полностью закрываются непрозрачным тёмным экраном с просьбой повернуть устройство. После поворота прохождение продолжается. Экран учитывает динамическую высоту окна браузера, вырезы и нижний системный индикатор.

Основная иллюстрация целиком вписывается в безопасную область без растяжения или обрезки. Свободное место заполняет затемнённая размытая копия того же кадра. Интерактивные области совпадают с основной иллюстрацией.

У кнопок и областей предметов минимальная область нажатия 48 × 48 логических пикселей. Картинка интерактивной сцены и предметы используют одну геометрию внутри безопасной области. Длинные реплики, варианты выбора, меню и финал прокручиваются. Анимация текста приостанавливается при открытом меню и уходе приложения в фон. Кнопка «Назад» Android открывает игровое меню; из главного меню возвращает к игрокам.

`expo-image` поддерживает WebP на Android и iOS и сохраняет загруженные изображения в дисковом кэше. Для встроенной версии при недоступности удалённой картинки используется её встроенная копия. Новые удалённые сцены требуют доступного изображения или ранее заполненного кэша. Веб-манифест и иконки позволяют добавить ярлык на домашний экран в поддерживающих это браузерах. Service worker не добавлен: полного офлайн-режима веб-версии пока нет.

## Проверка на телефоне без APK

```powershell
npm ci
npm run build:web
npm run preview:lan
```

Сервер напечатает IP-адрес компьютера. Открой адрес на телефоне в той же Wi-Fi сети. Обычный `npm run preview` доступен только на компьютере. Для проверки запуска с домашнего экрана и поведения HTTPS используй опубликованную статическую сборку; HTTP в локальной сети подходит для проверки интерфейса.

Для обычного прохождения в Expo Go сканируйте опубликованный QR-код в README: компьютер и локальный сервер не нужны. Expo Go должен поддерживать SDK 57; на iOS требуется вход в аккаунт внутри Expo Go. Для локальной разработки можно использовать `npm start` и QR-код терминала; телефон и компьютер находятся в одной сети, а Expo CLI и Expo Go на iOS используют один аккаунт.

Браузерная проверка размеров экрана не заменяет проверку Safari на настоящем iPhone, поведения клавиатуры и системных жестов. Android APK дополнительно проверяется на эмуляторе.

## Сохранения

Профили, сцены, реплики, решения и найденные улики автоматически записываются через AsyncStorage. В браузере используется localStorage сайта, в нативном приложении — хранилище приложения. После закрытия и повторного запуска выберите профиль и продолжите историю. При обновлении сюжета сцены сопоставляются по устойчивым ID; совместимые решения сохраняются. Если встроенный сюжет новой APK новее сохранённого кэша, используется встроенная версия; более новое скачанное обновление продолжает загружаться из кэша.

У браузера, Expo Go и APK отдельные данные. Синхронизации между устройствами и браузерами нет. Приватный режим, очистка данных сайта или приложения и удаление приложения могут удалить сохранения. Новую APK устанавливайте поверх предыдущей с тем же идентификатором и подписью.

APK содержит встроенный сюжет и иллюстрации и запускается без сети. Удалённые обновления и новые ресурсы требуют подключения. Expo Go первоначально загружает проект из Expo; у веб-версии пока нет гарантированного офлайн-запуска.

## Проверка сборки

```powershell
npm run prepare:story
npm run check
npm test
npm run build:web
npm run check:mobile
```

Последняя команда экспортирует JavaScript и ресурсы Android/iOS в `artifacts/mobile-export/`. Она проверяет сборку двух платформ и не создаёт APK/IPA.

## Публикация и мобильная сборка

Для браузера размести содержимое `dist/` на статическом HTTPS-хостинге. Пути манифеста и иконок относительные, поэтому поддерживается публикация в подпапке. Для `story.json` требуется `Cache-Control: no-store`; при размещении данных на отдельном домене разреши CORS. `public/_headers` содержит готовые правила для хостингов, понимающих этот формат; на других настрой эквивалентные заголовки. При обновлении сначала загружай новые картинки, затем JSON. Не удаляй изображения предыдущей версии немедленно: открытые игры могут ещё использовать её.

Для обновлений нативного сюжета используется `EXPO_PUBLIC_STORY_URL` из preview-профиля и Android workflow. Expo Update подключён к проекту команды `arishkawolfs-team`; канал `preview` связан с одноимённой веткой.

Для новой публикации Expo:

```powershell
npx expo login
npm run publish:expo -- "Краткое описание обновления"
```

Скрипт готовит арт, публикует iOS и Android и обновляет ссылки и QR-коды в README. После этого отправьте изменения в GitHub. При изменении нативных библиотек обновляйте версию приложения и собирайте новый APK/IPA.

Для APK в GitHub откройте **Actions → Build Android APK → Run workflow**. После проверки APK публикуется в **Releases**. Workflow генерирует Android-проект через Expo Prebuild, собирает release APK, проверяет подпись и запускает его на Android-эмуляторе. Проверка создаёт профиль, сохраняет реплику, закрывает и повторно открывает приложение, проверяет восстановление и вертикальную блокировку. Скриншоты находятся в артефакте `Android-device-check`.

Это preview APK с тестовой подписью. Для Google Play используйте профиль `production` и постоянный ключ владельца. [Установка APK](MOBILE_APK.md).

`app.json` содержит иконки, параметры экрана запуска и идентификаторы приложения. Профиль `ios-simulator` создаёт сборку для симулятора на Mac, которая не устанавливается на iPhone. Internal/ad hoc установка на iPhone и TestFlight требуют настройки подписи Apple. [Правила распространения Expo](https://docs.expo.dev/build/internal-distribution/).

Нативные каталоги генерируются при сборке; ключи подписи и локальные артефакты не добавляются в репозиторий.

Перед релизом проверь на настоящем Android и iPhone: ввод имени с клавиатурой, поворот в обе стороны, длинные реплики и выборы, поиск трёх улик и записку, уход в фон/возврат, перезапуск с сохранениями нескольких игроков, обновление сюжета, экран запуска и системную кнопку «Назад» Android. Проверь отдельно запуск из браузера и с ярлыка домашнего экрана. На iOS нужные проверки включают Safari и вырез/нижний индикатор; на Android — Chrome и системную навигацию.
