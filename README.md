# Капибара-рыцарь

Визуальная новелла на React Native + Expo + TypeScript для браузера, Android и iOS. Подключено 43 изображения в 46 сценах: `scen4-3` повторяется при рассказе о свидетеле, а `scen11-1` используется для ответов Дикобраза и прощания. После поиска улик капибара остаётся на ночь в деревне или сразу возвращается в таверну. Обе ветки приводят к записке отсутствующего хозяина и отдыху в комнате наверху. После пробуждения можно поговорить с Дикобразом или сразу поехать к волкам. Текущая граница сюжета — прибытие к охраняемому входу в деревню волков в `scen12-2`. Музыка пока не подключена.

## Запуск

Нужен Node.js 22.13 или новее. Открой терминал в этой папке:

```powershell
npm install
npm run web
```

Для телефона:

```powershell
npm start
```

Открой QR-код в Expo Go, совместимом с Expo SDK 57. Компьютер и телефон должны быть в одной сети. Если SDK ещё не поддерживается установленным Expo Go, потребуется обновление Expo Go или development build. `npm run android` открывает Android-эмулятор, если он установлен. Симулятор iOS требует macOS; на Windows можно тестировать физический iPhone через Expo Go.

## Управление и экран

- В игре нажимай на **правую половину экрана**. Сначала появится реплика, затем следующая реплика или картинка. Сцены без текста сразу переключаются.
- Во время анимации нажатие показывает текст целиком. Панель плавно появляется, а чёрный текст раскрывается слева направо. Системная настройка уменьшения анимации учитывается.
- На `scen4-1` нужно выбрать напиток. Все шесть напитков ведут на `scen4-2`; выбранный напиток сохраняется.
- На `scen7-6` капибара благодарит свидетеля. На `scen7-7` игрок выбирает: отказ завершает игру, помощь и осмотр дома ведут на `scen8`.
- В `scen8-2` после вводных мыслей включается осмотр. Нажимай на шерсть, отпечатки лап и иглу на самой картинке. Каждая находка открывает отдельные мысли. Уже найденную улику можно осмотреть снова — она сохраняется только один раз. Количество находок и общее количество улик на экране не показываются.
- Во время поиска нажатие справа не пропускает комнату. «Закончить осмотр» доступно и без находок: капибара прекращает поиск и переходит к решению о ночлеге. «Подсказка» выделяет шерсть и отпечатки лап; игла остаётся без обводки, маркера и изменения курсора при наведении. Все последующие упоминания иглы появляются только после её обнаружения. Белая панель скрыта между осмотрами, чтобы не закрывать пол.
- На `scen8-3` мысли зависят от найденных предметов. Любая комбинация, включая ни одной улики, допускает оба маршрута. Ночлег: `scen8-4` → `scen8-6` → `scen8-7` → `scen8-9` → `scen9` → `scen9-2_2`. Немедленный отъезд: `scen8-5` → `scen8-8` → `scen9-1` → `scen9-2`.
- В `scen9` и `scen9-1` после вводных реплик нужно нажать на записку на стойке. Обычные нажатия справа и клавиши продолжения не переключают кадр. Откроется соответствующая утренняя или ночная картинка чтения; текст записки одинаковый. После всех её реплик обе ветки сходятся в `scen10` → `scen10-1` → `scen10-2`. Мысли перед сном учитывают найденные улики.
- В `scen10-3` капибара просыпается от голосов и выбирает разговор с Дикобразом или прямой отъезд к волкам. Если шерсть и следы не найдены, основанием проверить волков служит рассказ Шиншиллы о рычании.
- Разговор ведёт в `scen11` → `scen11-1`: можно попытаться рассказать об осмотре и уликах или уйти. Попытка приводит в `scen11-1-clues`, где после отказа доступен только выбор «Уйти». Обе версии прощания используют `scen11-1-leave`.
- Все маршруты сходятся в `scen12`: после разговора капибара вспоминает раздражение Дикобраза, при прямом отъезде — найденные следы. Игла усиливает подозрения только если найдена и разговор состоялся. В `scen12-1` видна деревня вдали; следующий кадр `scen12-2` показывает капибару у входа, где он замечает охрану и решает, как представиться и к кому обратиться.
- Перед главным меню выбери локального игрока или нажми «Добавить игрока». Имя можно изменить в списке профилей. У каждого игрока своё прохождение, игровые переменные и дата последней игры; в списке видна текущая глава.
- Меню `•••`: продолжить, вернуться в главное меню, сменить игрока, начать заново, проверить обновления. Сменить игрока можно также внизу главного меню. Новая игра требует подтверждения и заменяет только сохранение выбранного игрока.
- В браузере доступны →, пробел и Enter для продолжения, Escape для меню и кнопка полного экрана.

Обычные картинки занимают весь экран в режиме `cover`: пропорции сохраняются, а края могут обрезаться при отличии формата экрана от картинки. Комната с поиском и сцены с обязательной запиской показывают весь арт в режиме `contain`, чтобы предметы оставались видимыми. Области нажатия масштабируются вместе с изображением; минимальный размер — 44 пикселя. В мобильном приложении задана горизонтальная ориентация. В браузере принудительный поворот поддерживается не везде, поэтому в вертикальном окне показывается просьба повернуть устройство. Вырезы экрана учитываются при размещении кнопок и диалогов.

## Где менять сюжет

`public/story.json` — основной файл сюжета. Массив задаёт порядок сцен в просмотровом сценарии; игровой маршрут определяют `next` и выборы. Идентификаторы сцен сохраняй стабильными. Вторая сцена использует `photo/scen2.png`. Новый арт для рассказа свидетеля сохранён с предоставленным именем `photo/сцена7-5.png`; кириллица в именах поддерживается.

Девятая сцена имеет отдельный ID `scen4-3-witness` и снова использует `photo/scen4-3.png`. Поэтому рассказ о нападении и рассказ о Шиншилле содержат разные реплики и занимают отдельные места в сохранениях, хотя показывают один и тот же арт. Мысли капибары помечены именем говорящего `Капибара · мысли`.

Для чтения всех реплик по порядку есть `Сценарий.md`. Это просмотровая копия, которая автоматически создаётся из JSON при `npm run prepare:story` и сборке. Правки для игры нужно вносить в `public/story.json`.

Пример сцены с двумя репликами:

```json
{
  "id": "scen3",
  "image": "photo/scen3.png",
  "chapter": "Пролог",
  "dialogues": [
    { "speaker": "Рассказчик", "text": "Первая реплика." },
    { "speaker": "Капибара", "text": "Вторая реплика." }
  ],
  "next": "scen4"
}
```

Пустой `dialogues: []` показывает только картинку. Для очень длинных реплик лучше разбивать текст на несколько реплик; панель также прокручивается, если содержимое не помещается на маленьком экране. В сценах с `choices` обычный переход блокируется до выбора. `next: null` завершает историю. У выбора можно указать `ending: { "title": "...", "text": "..." }` для отдельного финала.

Шесть переменных состояния:

| Переменная | Назначение |
| --- | --- |
| `drink` | Название выбранного напитка или `null` |
| `courage` | Счётчик смелости, увеличивается при решении расследовать |
| `clues` | Счётчик уникальных найденных улик |
| `helping` | Решила ли капибара помогать |
| `evidence` | Список ID найденных улик: `fur`, `paws`, `quill` |
| `talkedToPorcupine` | Состоялся ли разговор с Дикобразом после пробуждения; изначально `false` |

В `effects` выбора строки и логические значения заменяют переменную, числовые значения прибавляются к счётчику. Маршрут задаётся через `next`; условные реплики используют `condition.found`, `condition.missing` и `condition.talkedToPorcupine`. Условия объединяются: например, `{"found":["quill"],"talkedToPorcupine":true}` требует и найденной иглы, и разговора. Игла хранится в `evidence` и остаётся доступна для будущих сцен в любом ночном маршруте. Для поиска не нужно добавлять отдельную переменную на каждый предмет.

Сцена осмотра содержит `search.imageSize`, `search.hotspots` и `search.finishLabel`. Каждая область имеет ID улики, название, реплики и прямоугольник `rect` в долях исходной картинки (координаты от 0 до 1). При замене арта нужно сверить размеры и расположение областей. Условия и области поиска проверяются перед применением обновлений.

Обязательная записка задаётся через `interaction.id`, `interaction.label`, `interaction.imageSize` и `interaction.rect`; `next` ведёт в кадр чтения. После вступления прогресс хранит `interacting: true`, и обычный переход блокируется до нажатия на предмет. Записка не добавляется к уликам и не меняет их количество. Сохранение в ожидании нажатия восстанавливает ту же блокировку.

Состояние разговора и условия маршрута используют `schemaVersion: 4`; интерактив с запиской появился в версии 3. Новый клиент читает версии формата 1–4. Старые сохранения получают отсутствующие поля: `evidence: []` и `talkedToPorcupine: false`. Клиенты предыдущих версий отклоняют новый формат, чтобы не потерять условия маршрута. Нужно обновить страницу или мобильную сборку. Для обычных изменений реплик по-прежнему меняй только поле `version`.

## Как добавить картинку

1. Положи файл в исходную папку `photo/` с именем вроде `scen9.png`.
2. Добавь сцену в `public/story.json` и обнови `next` предыдущей сцены. Для iOS/Android без хостинга добавь статический `require('../photo/scen9.png')` в `src/assets.ts`.
3. Измени `version` в `story.json` при любом изменении текста, переходов или изображений, например на `2026-10-07.4`. Текущий `schemaVersion: 4` сохраняй.
4. Выполни `npm run build:web`. Фотографии автоматически копируются в статическую сборку. Исходники в `photo/` сохраняются.

## Статический хостинг и обновления

```powershell
npm run build:web
npm run preview
```

`dist/` — готовая папка для любого статического хостинга. `preview` — только локальный просмотр на `http://localhost:4173`; на хостинге серверный код не нужен.

В браузере приложение проверяет `story.json` рядом с собой. Для мобильного приложения создай `.env` по `.env.example` и задай `EXPO_PUBLIC_STORY_URL` — полный HTTPS-адрес размещённого `story.json`. Перезапусти Expo после изменения `.env`. Данные, картинки и клиентское приложение остаются статическими.

Проверки выполняются при запуске, возврате в приложение и раз в минуту. Есть ручная кнопка проверки. Новая версия предлагается баннером и применяется по нажатию. Игра проверяет формат, ссылки между сценами, выборы и переменные; некорректный JSON не заменяет текущую историю. При обновлении сохраняются переменные и текущий ID сцены; её диалоги открываются заново. Если сцену удалили, игра начинает сюжет сначала и сообщает об этом. Финал старой версии также переоткрывается, чтобы не блокировать добавленное продолжение.

Профили с отдельными сохранениями и последний принятый JSON лежат локально через AsyncStorage. Коллекция игроков хранится одним документом `capybara.players.v1`: стабильный ID, имя (1–40 символов), дата создания, дата последней игры и прогресс каждого игрока. Записи выполняются по очереди, чтобы быстрое переключение профилей не смешивало прохождения. Создание и переименование профиля не меняет дату последней игры. Одинаковые имена без учёта регистра не допускаются.

Прежнее общее сохранение `capybara.progress.v1` автоматически переносится в профиль «Игрок 1», который можно переименовать. Исходный ключ остаётся резервной копией; при последующих запусках используется коллекция профилей. При обновлении сюжета проверяются сохранения всех игроков; повреждённое сохранение или удалённая сцена одного игрока не сбрасывает остальных. Выбор игрока показывается при каждом запуске. Профили не синхронизируются между устройствами и браузерами; очистка данных сайта или приложения удалит локальные данные.

Встроенный сюжет и картинки позволяют запустить первоначальную версию без хостинга. Доступность новых удалённых картинок без интернета зависит от кэша устройства; при ошибке предусмотрена кнопка повтора.

При публикации сначала загружай картинки, затем `story.json` с новой версией. Версия добавляется к URL изображений, чтобы обновлённый арт не оставался в старом браузерном кэше. Для `story.json` на хостинге задай `Cache-Control: no-cache` либо `no-store`; приложение дополнительно использует запрос без кэша. Если JSON и браузерное приложение размещены на разных доменах, хостинг данных должен разрешать CORS. Изменения самого UI требуют новой web-сборки или обновления мобильного приложения.

## Проверки и структура

```powershell
npm run check
npm test
npm run build:web
```

- `App.tsx` — экраны, фон, управление и выборы.
- `src/Dialogue.tsx` — анимация панели и текста.
- `src/Inspection.tsx`, `src/geometry.mjs` — поиск предметов и области нажатия для разных экранов.
- `src/SceneInteraction.tsx` — обязательное нажатие на записку.
- `src/PlayerSelect.tsx`, `src/profiles.mjs` — выбор, создание, переименование, независимые сохранения игроков и перенос старого прогресса.
- `src/engine.mjs` — переходы, состояние и проверка обновлений.
- `src/repository.ts`, `src/useNovel.ts` — загрузка, кэш, сохранения и проверка версий.
- `public/story.json` — редактируемые данные новеллы.
- `photo/` — оригиналы арта.
- `tests/engine.test.mjs` — обязательные выборы, оба исхода, все изображения и изменения сюжета.
- `tests/inspection.test.mjs`, `tests/note.test.mjs` — сочетания улик, оба маршрута, обязательная записка, сохранения и расположение предметов на разных экранах.
- `tests/wolves.test.mjs` — три пути к волкам для всех сочетаний улик, обязательные выборы, условные мысли и совместимость сохранений.
- `tests/profiles.test.mjs` — независимость профилей, переименование, миграция старого сохранения, обновления всех игроков, повреждения и порядок записи.

Стек и ориентация сверены с официальной документацией: [Expo SDK](https://docs.expo.dev/versions/latest/), [ScreenOrientation](https://docs.expo.dev/versions/latest/sdk/screen-orientation/).

При установке `npm audit` сообщил о 23 уязвимостях в дереве зависимостей, включая транзитивные зависимости инструментов Expo/Metro. Предлагаемое принудительное исправление откатывает Expo до 44 и React Native до 0.72, поэтому оно не применялось: это нарушило бы совместимость SDK 57. Этот результат относится к зависимостям и требует отдельного обновления стека при появлении совместимых исправлений.
